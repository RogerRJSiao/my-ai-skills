# 改善提案表 撰寫操作建議

> 適用對象：撰寫「改善提案表」前參考使用
> 本文件與 `improvement-proposal-draft` skill 內容一致，可作為離線紙本或教育訓練參考

---

## 一、四段式架構

| 區塊 | 內容 |
|---|---|
| **提案名稱** | 20字以內，加分類標籤（共9種，見下表），可複選（如【品質/效率】），建議不超過2個 |
| **現狀缺失** | 背景/制度 → 現行做法侷限 → 造成的風險或成本，1~2句話講完 |
| **改善內容** | 總述目的與方法 + 分點列出做法(建議3~4點) |
| **相關檔案/連結** | 選填，附上SharePoint、GitLab、維護單號等佐證 |

---

## 二、「現狀缺失」三層公式

1. **背景/制度**：為何存在這件事
2. **現行做法的侷限**：具體指出沒效率或有風險的做法
3. **造成的後果**：遺漏、耗時、逾時失敗等，能量化就量化(附錯誤代碼、單號)

**注意**：
- 避免同一件事重複描述兩次
- 若有錯誤訊息可直接引用精簡帶過，不要寫「如附圖：」這種依賴外部圖片的贅詞，文字本身要能獨立說明清楚

---

## 三、「改善內容」寫作技巧：專業詞彙 + 白話科普

這是讓非技術主管也能看懂提案的核心技巧：

1. 每點先給白話小標題（括號內），再寫專業做法
   - 範例：`源頭篩選優化(篩選交給資料庫先做)`
2. 專業詞彙第一次出現時用生活化比喻解釋一次即可，之後可簡化不必每次展開
   - WHERE子句 →「先跟倉庫說好要哪些貨，直接送需要的」
   - 索引(index) →「類似目錄，可快速定位資料」
3. 避免英文直譯或過度抽象的詞，依審核對象調整：
   - 面向非技術主管：用最白話的詞（如「源頭篩選」）
   - 面向IT/工程背景：可保留專業詞+英文對照（如「查詢下推(Predicate Pushdown)」）
4. **誠實寫出限制條件**，不要為了讓提案完美而省略
   - 例：`CommandTimeout`只能延長用戶端等待，仍會受資料庫伺服器逾時設定影響
5. 分點建議3~4點，**最後一點通常收斂在「文件化/命名規則/版控」**，讓提案有制度化、可長期維護的收尾感

## 四、提案類別完整清單與判斷依據

正式申請表的分類下拉選單共9種，依提案內容判斷主要動機來選擇，**不要只在品質/效率兩者間打轉**：

| 分類 | 適用情境 |
|---|---|
| 效率 | 縮短作業時間、自動化流程、效能優化 |
| 品質 | 提高資料正確性/一致性、減少錯誤或遺漏 |
| 成本 | 能明確換算成金額節省(需搭配效益分析填年節省金額) |
| 生產 | 產線、製程、產能、良率相關 |
| 環境 | 節能減碳、廢棄物減量、環保法規 |
| 安全 | 降低職業災害、設備/系統操作安全 |
| 衛生 | 工作場所或食品/化學品衛生管理 |
| 防災 | 消防、天災應變、緊急應變、備援機制 |
| 其他 | 上述皆不符合時使用 |

**判斷原則**：先問「這個提案主要是為了省時間、省錢、防錯誤、還是防意外」，主要動機對應的分類放第一位；可複選但不建議超過2個。

## 五、台灣用詞檢查清單

| ❌ 避免 | ✅ 台灣慣用 |
|---|---|
| 数据/数据库 | 資料/資料庫 |
| 文件 | 檔案 |
| 超时 | 逾時 |
| 软件／硬件 | 軟體／硬體 |
| 视频 | 影片 |

不確定時，優先採用公司內部系統畫面（BPM、ERP、PBI）中既有的用語，不要自創替代詞。

## 六、送出前排版檢查清單

- [ ] 編號後有加空格（`1. xxx`），全份文件格式一致
- [ ] 沒有殘留個人筆記標記，如`[不寫]`、`[備用]`、`TODO`
- [ ] 分類標籤已對照「提案類別完整清單」確認，非直接套用品質/效率兩種
- [ ] 程式碼註解分類若被提及，需與原始程式碼逐一對照，避免漏列
- [ ] 連結、單號格式一致，並自行確認連結有效性

---

## 七、建議工作流程

```
1. 蒐集技術素材(程式碼/SQL/截圖/CHANGELOG)
        ↓
2. 用表格整理差異點，跟提案人確認理解正確
        ↓
3. 依「現狀缺失」公式草擬
        ↓
4. 依「改善內容」公式(專業詞彙+白話)草擬分點
        ↓
5. 跑一次「台灣用詞檢查」+「排版檢查」
        ↓
6. 提案人確認OK → 視需要轉存Word檔
```

---

## 八、使用限制提醒

- 不會自動判斷分類標籤絕對正確，僅提供建議，最終仍需依公司審核制度確認
- 不會驗證外部連結（SharePoint、GitLab等）是否仍然有效
- 不會捏造未提供素材中的技術細節或數據，若資訊不足會主動詢問
