# S06 Excel實作 — 逐項評分細則與檢查方法

本文件補充評閱標準 `S06_excel_scoring_criteria_v<最大版本>.xlsx`（梯次的
`01_template/`，沒有梯次時用本 skill 的 `assets/01_template/`）的文字敘述，記錄「怎麼從
.xlsx 檔案裡技術性地驗證每一小項」，以及批改過程中已經遇過的實際案例（正確
做法 / 常見錯誤）。搭配 `engine/extract_submission.py` 的輸出一起讀。

**標準的優先順序**：評閱標準 xlsx（最新版本）＞ 本文件 ＞ `engine/` 的 py 程式。
本文件與程式都是照 xlsx 寫的，三者若不一致，一律以 xlsx 為準，回頭修改本文件與
程式，不要反過來遷就程式的現況。改完後跑 `python scripts/check_rubric.py --batch <yyyymm>`（以梯次 01_template 的評閱標準為準）：它比對
配分表、評分標準文字裡的關鍵數值（範圍、儲存格、標籤、門檻）與 engine 常數及本文件，
並試評標準解答檔；評分標準文字的語意（例如何時直接0分）仍要人工對照本文件。

**工作表名稱**：【薪資】【成績】【車輛銷售】【武將能力】四個工作表名稱允許加
前後綴（例如「1.薪資」「成績_作答」「車輛銷售(完成)」）。對應規則：名稱完全
相同（忽略前後空白）的優先；否則取唯一一個名稱含該文字的工作表。實際對應
寫在 `sheet_names`（例如 `{"薪資": "1.薪資"}`），有前後綴時評分結果會附一條
提醒。多個工作表都含同一文字時列在 `ambiguous_sheets`、不自動挑選；完全找
不到則列在 `missing_sheets`。這兩種情況該大題以0分計，評閱結果說明寫出原因
（例如「有多個工作表名稱含『薪資』（薪資1、薪資作答），無法判斷要評哪一個」），
並提醒人工確認。原始資料比對（3.x／4.x）時，學生端用對應到的工作表，題目檔端
仍用原名稱。

**自動評分標成需人工確認（`needs_review`）的情況**一覽（細節見各小項）：
1.x 樞紐表來源解析不出是哪個活頁與範圍；1.4 樞紐輸出區找不到數值格；
2.1 凍結窗格設在 B3／A3／B1／A1 以外的位置；2.4 檔案沒有計算結果、又沒有
個人平均由大到小的排序條件；3.1／4.1 沒有提供題目檔、無法檢查原始資料；
3.x【車輛銷售】的候選圖表只有直方圖等新式圖表（chartEx）；3.4 用資料表而非
資料標籤；4.3 雷達圖 `radarStyle=marker` 但沒指定標記符號。

## 考題1. 薪資（樞紐分析）

**判斷有無樞紐表（1.1 的前提）**：用 `engine/extract_submission.py` 的
`pivot_薪資` 欄位判斷。樞紐表可以放在【薪資】活頁，也可以放在其他活頁
（Excel 插入樞紐表預設會開新活頁，例如「1.男女平均薪資」），但**來源必須是
【薪資】活頁的 A1:J13**：
- 來源是儲存格範圍時，`worksheetSource` 的 `sheet` 要是薪資、`ref` 要是 A1:J13
  （忽略 `$`）。
- 來源是表格時，表格要定義在薪資活頁上、範圍是 A1:J13。
- 來源是活頁簿層級的定義名稱時，名稱要指向 薪資!A1:J13。

實際所在活頁與範圍寫在 `host_sheet` / `location`。**【考題】活頁上的範例樞紐表
一律排除**（名稱含「考題」的活頁不找；那個範例的來源也是外部活頁簿，同樣會被
排除）。先找【薪資】活頁本身，再找其他活頁，取第一個符合的。

若 `pivot_薪資` 為 `null`，代表沒有符合的樞紐表 → **1.1~1.5 全部 0 分**（不用再
檢查其他小項）。有樞紐表但來源不符時列在 `pivot_薪資_rejected`，評閱結果說明
會寫出原因：來源範圍不是 A1:J13（例如 薪資!A1:J10）、來源是其他活頁，或來源
解析不出是哪個活頁與範圍（這一種會標成需人工確認）。

**1.2 欄列標籤**（10分）：看 `col_visible_labels` / `row_visible_labels`。
- 欄標籤（col）不是「業務、會計、門市」其中的項目（包括沒有欄標籤、或欄標籤
  放的是男、女）→ **1.2 直接0分**。
- 列標籤（row）不是剛好「男、女」→ **1.2 直接0分**。
- 以上都通過時，欄標籤只留下「業務」→ 10分；沒有只留下業務（例如三個部門全列）
  → 扣5分，給5分。

**1.3 彙總方式**：看 `data_fields[0].subtotal`。`"average"` 給滿分；
`"sum"` 給一半（Excel 在加總時常省略 subtotal 屬性，`null` 也視為加總）；其他給0。

**1.4 貨幣格式**：**不要只看 pivotField 的 numFmtId**——很多檔案
`applyNumberFormats="0"`，代表 pivot 自己的格式設定不會套用，實際顯示格式
要看 pivot 輸出區塊（`location` 範圍）儲存格本身的 `number_format`（`value_number_formats`
欄位）。只看格式的正數段（第一個 `;` 之前）：
- 「$」在數值（`0`／`#`）前面 → 滿分，例如 `"$"#,##0.00`、`[$$-409]#,##0`。
  `$` 在數值後面不算。
- 「通用格式」或純數值格式（如 `0`、`#,##0.00`）→ 半分。
- 其他 → 0分。

輸出區找不到任何數值格（`value_number_formats` 為空）時給0分並標成需人工確認。

**1.5 額外加分（來源為表格）**：看 `source_is_named_table`。樞紐表來源是
定義在【薪資】A1:J13 的 Excel 表格（`source_name_or_range` 是表格名稱，例如
`"salary"`）→ 給滿額外加分（6分）。來源是儲存格範圍或一般的定義名稱，都不算
「設為表格」。

## 考題2. 成績

用 `grades_sheet_info`（腳本 `成績` 欄位）逐項核對：

- **2.1 凍結窗格**（4分）：`freeze_panes == "B3"` → 滿分。如果只固定列
  或只固定欄（例如 `"A3"` 或 `"B1"`），各給一半（列是第3列給2分、欄是 B 欄
  給2分）。凍結在 B3／A3／B1／A1 以外的位置（例如 `"C3"`）時照此計分，並標成需
  人工確認；沒有凍結窗格則0分。
- **2.2 合併後置中**（4分＝設定2＋標題2，兩部分各自計分）：
  `a1_merge_and_center` 為真（A1:G1 合併儲存格，且 A1 水平對齊為「置中」，
  `a1_horizontal == "center"`）→ 設定2分。以下情況設定這2分都給0：
  - 合併範圍不是剛好 A1:G1（`a1_merged_range` 例如 `"A1:H1"`）。
  - 只合併沒置中。
  - 已合併但對齊是「跨欄置中」（`a1_horizontal == "centerContinuous"`），因為
    評閱標準要求的是「合併後置中」。
  - 只設跨欄置中而沒合併（`a1_merged_range` 為 `null`）。

  `header_text_preserved`（A1文字是「經濟甲班 期中考成績表」）→ 標題2分，
  不論設定是否正確。
- **2.3 公式與範圍**（9分）：`g3_g15_average_formulas_ok`（G3:G15 都用
  AVERAGE）給一半；`row_avg_formulas_ok` 且 `row_avg_integer_format`（班平均列
  B:F 用 AVERAGE，且每個計算結果都只保留到整數位）給另一半。「只保留到整數位」
  是指下列其中一種：
  - 儲存格格式的正數段沒有小數位，例如 `0`、`#,##0`、`0_);[Red]\(0\)`；
    「通用格式」不算。
  - 公式外層用 `ROUND(…,0)`／`ROUNDUP(…,0)`／`ROUNDDOWN(…,0)`／`INT(…)`。

  **注意**：先用 `avg_row_index` 確認「班平均」是哪一列，不要預設一定是第16列。
  班平均列用 `SUBTOTAL(101,…)` 或其他函式取代 AVERAGE（`row_avg_uses_subtotal`
  為真）→ 班平均這一半給0。
- **2.4 排序與篩選**（10分＝排序5+篩選5，兩者互相獨立）：
  - **排序**：看結果。`g_values_descending` 為真（G3:G15 個人平均的計算結果由大
    到小）→ 5分。不看是否留有排序條件，所以排序後 Excel 沒保留 `sortState`
    也照樣給分。檔案沒有計算結果時（`g_values_descending` 為 `null`，例如不是
    Excel 存的檔），改看 `sort_conditions` 有沒有個人平均（G欄）由大到小；兩者
    都沒有時給0分並標成需人工確認。
  - **篩選條件從哪裡讀**：【成績】活頁上的表格（題目檔的「表格2」）以及活頁本身的
    自動篩選都會讀，所以學生把表格轉成一般範圍再篩選、排序也照樣評分。
    `filter_conditions` 的 `column` 是篩選所在的工作表欄位（由 `col_id` 加上篩選範圍
    的起始欄換算，個人平均是 G 欄）。
  - **篩選**：`filter_conditions` 有個人平均欄（`column == "G"`）的數字篩選
    val=70，operator 為 `greaterThan`（>70）或 `greaterThanOrEqual`（≥70），
    **而且**最後只留下9列資料（`visible_data_rows == 9`：8位學生加上班平均）
    → 5分。條件正確但留下的列數不是9（通常是篩選沒有真的套用）→ 0分。用勾選
    數值清單篩選（`operator == "values"`）或篩選在其他欄位，都不算「數字篩選
    > 70」，給0分。注意 `filter_gt70_applied` 只認 `greaterThan`，判斷時以
    `filter_conditions` 為準。

  常見錯誤是「只排序、忘記篩選」。
- **2.5 框線**（3分）：`borders_complete` 為真才給分，否則0分（依標準沒有
  半分選項，此項是全有全無）。檢查範圍固定是 A1:G16（與班平均在哪一列無關），
  儲存格任一邊有框線就算有。
- **2.6 額外加分（G16留空）**（3分）：G16 這一格不可填入任何 Excel 公式、數值或
  文字，`g16_cell.is_empty` 為真就給分（固定看 G16，與班平均在哪一列無關）。
  曾出現的錯誤案例：學生把「個人平均」那欄也往下拉出 `=AVERAGE(G3:G15)`，這樣
  G16 就有公式了，不能給這項加分（但不影響 2.3 的分數，因為 2.3 只看 B:F 欄）。

## 考題3. 車輛銷售（動態直條圖）與 考題4. 武將能力（動態雷達圖）

兩題判斷邏輯相同，差別只在圖表類型與座標軸/圖例應顯示的內容。

**第一步：判斷原始資料是否被更動（極重要，會讓整大題歸零）**

用 `--question` 參數提供原始題目檔（`assets/01_template/S06_excel_question_v1.xlsx`），
腳本會輸出 `車輛銷售_raw_data_check` / `武將能力_raw_data_check`，比較
**第A欄與第2列**是否與原始題目完全一致：車輛銷售比對 A2:A6 與 A2:E2（含 A2
「廠牌」、E2「總計」），武將能力比對 A2:A7 與 A2:E2。題目檔是空白的格子（例如
武將能力 A2）學生也不可填入；範圍以外的格子（例如車輛銷售 A7、A1 的標題）不比對。**只要有任何一格不同（`unchanged: false`），該大題
（3.1~3.4 或 4.1~4.3）全部給0分**，不用再檢查圖表細節。已知案例：學生把
「一月/二月/三月」改成「十一月/十二月/十三月」，這樣即使圖表技術上仍是動態的，
也要整題歸零。

沒有提供題目檔時不做這項檢查（`*_raw_data_check` 不會出現），3.1／4.1 照常
計分但標成需人工確認，評分結果也會附一條提醒。

比對時會先去掉前後空白再比較：題目檔武將能力 D2「程遠志」本身帶一個結尾 Tab
字元，學生把這個 Tab 刪掉**不算**更動原始資料（4.1 的例外），不會讓考題4歸零。

**多張圖表**：同一活頁有多張圖時（`chart_count > 1`），只評分「動態且類型正確」
的那一張（車輛銷售找 barChart、武將能力找 radarChart），其餘忽略；都不符合時
退回評第一張（通常就會因類型或非動態而整大題0分）。評分結果會附一條提醒。

**第二步：確認圖表是動態的**

`is_dynamic` 為真（`c:numRef`/`c:strRef` 存在，代表公式參照儲存格而非
寫死數值）。若 `literal_only` 為真（`numLit`/`strLit`，貼上固定數值），
該大題（3.x 或 4.x）全部0分。

**第三步：確認圖表類型（也會讓整大題歸零）**

- 考題3 只限長條圖、直條圖、直方圖：`chart_type == "barChart"`（直條圖、橫條圖都是
  barChart，`bar_dir` 為 `col`／`bar`）。立體群組直條圖（`bar3DChart`，`is_3d` 為真）
  也回報為 `barChart`，一樣給分。
- 考題4 只限雷達圖：`chart_type == "radarChart"`。
- 其他圖表類型（折線圖、圓餅圖、區域圖、散佈圖…）→ **該大題（3.1~3.4 或
  4.1~4.3）全部0分**。`chart_types` 列出圖表裡所有的圖表類型（組合圖會有多個），
  評閱結果說明寫出中文名稱，例如「圖表類型為區域圖，不是長條圖／直條圖／直方圖」。
- 直方圖是 Excel 2016 以後的新式圖表（chartEx），XML 格式不同，腳本不解析，只在
  `chartex_count` 計數。評閱標準說有多張圖表時只看動態的長條圖或直方圖，所以
  【車輛銷售】沒有可給分的一般圖表（沒有圖表、非動態或類型不對）但有直方圖時，
  考題3暫給0分並標成需人工確認，要開檔確認直方圖。【武將能力】只接受雷達圖，
  只有直方圖時直接0分，說明寫「活頁只有直方圖等新式圖表，不是雷達圖」。

**3.1 / 4.1 作答狀態**（各5分）：通過上面三步（資料未被更動、圖表為動態、圖表類型
正確）→ 滿分。

**3.2 座標軸設定**（15分，三等分）：
- 類別（`categories`）需恰好是 `["福特","賓士","裕隆","三菱"]`（順序不拘，
  但四個都要有、不能多也不能少）→ 5分。**常見錯誤**：把類別軸設成月份
  （一月/二月/三月），把廠牌放到圖例——這是把兩個維度對調了，類別軸這5分
  直接是0。
- `y_max` 為 2000 且 `y_major_unit` 為 500（以數值比較）兩者都對才給5分（其中一個
  錯就是0，不是各半）。
- `gridlines_none` 為真 → 5分。

**3.3 圖例設定**（5分）：`series_names` 需恰好是
`["一月","二月","三月"]`（順序不拘），少一個或多一個都是0分（此項沒有
半分）。

**3.4 額外加分**（9分，三項各3）：
- `has_data_labels` → +3（注意題目特別註明：如果學生用的是「資料表
  (Data Table)」而不是逐點資料標籤，兩者要區分清楚，`dLbls` 的
  `showVal` 才算一般資料標籤；資料表功能是另一個 XML 節點
  `plotArea/dTable`，腳本以 `has_data_table` 回報；`has_data_labels: false`
  但 `has_data_table: true` 時，打開 chart XML 人工確認）。
- `has_chart_title` → +3。
- `has_x_axis_title` 且 `has_y_axis_title`（兩者都要有才算，因為原題目
  要求「縱軸的數量」和「橫軸的廠牌」都要標）→ +3。

**4.2 座標設定**（10分，拆解5+5）：
- 類別軸（`categories`）需恰好是
  `["統帥","武力","智力","政治","魅力"]` → 5分（全對才給，任一缺漏0分）。
- 圖例（`series_names`）需恰好是 `["趙雲","周瑜","程遠志","劉禪"]` → 5分
  （原始資料裡「程遠志」字串可能帶有一個 tab 字元 `\t`，比對時先
  `.strip()` 再比較，避免因為看不見的空白字元誤判；同一個 Tab 在原始資料
  檢查的處理見上方 4.1 的例外）。

**4.3 額外加分**（6分，兩項各3）：
- `has_chart_title` → +3。
- 使用含資料點標記的雷達圖：檢查 `marker_symbols`，如果全部是
  `"none"` 代表雖然 `radarStyle` 可能設為 `"marker"`，但每個資料點的
  `c:symbol` 都是 none，等於沒有真的顯示標記 → 不給分。要看到
  `marker_symbols` 出現 `"circle"`／`"diamond"` 等非 none 的值才給分。
  `marker_symbols` 是空的（沒有指定任何符號）但 `radar_style == "marker"` 時，
  Excel 可能以預設標記顯示，這3分先不給，標成需人工確認。
